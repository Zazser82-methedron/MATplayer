# Визуальная система — Этап 1 направления A (дизайн)

Дата: 2026-08-05.

## Контекст

Пользователь попросил изучить дизайн реальных музыкальных плееров (ориентиры:
Spotify, Apple Music) и довести интерфейс MATplayer до такого же уровня.
Направление A из `docs/2026-07-26-gemini-research-prompt-round3.md` (визуальный
язык, переход между артистами, композиция кадра, идентичность сущностей,
иерархия, мобильный опыт) — слишком широкое для одной реализации и разбито на
4 независимых этапа:

1. **Визуальная система** (этот спек) — типографика, цвет, отступы, иконки,
   применение к существующим панелям.
2. Идентичность сущностей — библиотека/карточка артиста/альбом на новой
   системе, генеративная обложка альбома и визуальный маркер артиста.
3. Движение — переход между артистами, композиция кадра во время трека.
4. Мобильная полировка.

Этапы 2–4 в этот спек не входят.

## Проблема

Интерфейс собирался по одному компоненту за раз на протяжении нескольких
раундов правок. Результат:
- Цвет текста задаётся как `rgba(242, 237, 230, N)` с непоследовательным N
  (0.45/0.5/0.55/0.6/0.62/0.65/0.75/0.8) в каждом файле по отдельности —
  нет единой шкалы "насколько текст второстепенный".
- Отступы и радиусы — случайные числа (6/9/10/12/14/16/18/20/22 px) без
  системы.
- Кнопки — юникод-глифы (⏮ ❚❚ ▶ ⏭ ★ ☆ ⋯ 🔇 🔊 ✕), которые по-разному
  рендерятся на разных ОС/браузерах: разная толщина, оптический центр не
  совпадает с центром кнопки. Главный источник ощущения "собрано из кусков".
- `.seek-bar` и `.player-bar` — две отдельные плавающие капсулы одна над
  другой. Ни один референсный сервис так не делает: шкала времени всегда
  часть той же панели, что и транспорт.

## Решение

### Токены

Новый блок в начале `src/index.css`, `:root`:

```css
:root {
  /* Типографика */
  --font-display: system-ui, -apple-system, 'Segoe UI', Roboto, sans-serif;
  --text-2xl: 700 1.75rem/1.15 var(--font-display);
  --text-lg:  600 1.05rem/1.3 var(--font-display);
  --text-md:  500 0.9rem/1.4 var(--font-display);
  --text-sm:  400 0.8rem/1.4 var(--font-display);
  --text-xs:  600 0.72rem/1.3 var(--font-display); /* + letter-spacing 0.08em, uppercase на месте применения */

  /* Цвет */
  --ink: #f2ede6;
  --ink-muted: rgba(242, 237, 230, 0.62);
  --ink-faint: rgba(242, 237, 230, 0.45);
  --surface: rgba(10, 10, 10, 0.6);
  --surface-solid: rgba(12, 12, 12, 0.92);
  --border: rgba(255, 255, 255, 0.12);
  --border-strong: rgba(255, 255, 255, 0.2);
  --hover-overlay: rgba(255, 255, 255, 0.1);

  /* Отступы */
  --space-1: 4px;
  --space-2: 8px;
  --space-3: 12px;
  --space-4: 16px;
  --space-6: 24px;
  --space-8: 32px;

  /* Радиусы */
  --radius-sm: 10px;
  --radius-md: 16px;
  --radius-lg: 22px;
  --radius-pill: 999px;

  /* Blur/elevation — два уровня: плавающие панели vs модалки */
  --blur-panel: 18px;
  --blur-modal: 22px;
}
```

Существующие произвольные значения в `.player-bar`, `.library-panel`,
`.artist-card`, `.queue-panel`, `.seek-bar`, `.lyrics-overlay` заменяются на
эти токены. Значения, которые уже совпадают с токеном (например
`border-radius: 22px 22px 0 0` в карточке артиста), меняются на переменную
без изменения визуала — обратная совместимость по пикселям, где это уместно;
где токен предполагает сведение к единой шкале (радиусы 6/9/10/14/18/20 →
`--radius-sm`/`--radius-md`), визуал слегка меняется в сторону единообразия.

### Иконки

Новый файл `src/ui/icons.jsx` — набор маленьких SVG-компонентов (`viewBox="0
0 20 20"`, `stroke="currentColor"`, `fill="none"`, `strokeWidth={1.8}`,
`strokeLinecap="round"`, `strokeLinejoin="round"`):

`IconPlay`, `IconPause`, `IconPrev`, `IconNext`, `IconStar` (принимает
`filled: boolean` — заливка для избранного), `IconMore`, `IconClose`,
`IconMute`, `IconVolume`, `IconShuffle`, `IconRepeat` (принимает `mode: 'off'
| 'all' | 'one'` — для repeat-one рисует маленькую цифру `1` рядом), `IconQueue`,
`IconLink`.

Каждая иконка — чистый функциональный компонент без сторонних зависимостей
(без иконочных библиотек — по одному SVG-пути на кнопку, задача узкая).
`aria-hidden="true"` на самом SVG — семантика остаётся на `aria-label` кнопки,
как сейчас.

### Объединение seek-bar и player-bar

`SeekBar` перестаёт быть отдельной плавающей панелью и становится верхней
секцией внутри `.player-bar` (класс `.player-bar__progress`). Разметка
`PlayerControls`:

```
.player-bar
  .player-bar__progress   (бывший .seek-bar, без своего фона/blur/border)
  .player-bar__row
    .player-bar__meta
    .player-bar__transport
    .player-bar__end
```

`SeekBar.jsx` остаётся отдельным компонентом (принимает те же пропсы), но
теряет обёртку с `background`/`backdrop-filter`/`border` — их даёт родитель.
`App.jsx` передаёт `onSeek` в `PlayerControls`, а не рендерит `SeekBar` как
отдельный сосед — родительский компонент один, пропсов у `App.jsx` меньше.

### Область применения

Переводятся на токены и новый набор иконок: `PlayerControls.jsx` (+
поглощённый `SeekBar`), `Library.jsx`, `ArtistCard.jsx`, `QueuePanel.jsx`.

Отдельная находка при самопроверке спека: в проекте уже есть компонент
`VolumeControl.jsx` (с собственным тестом), но он нигде не импортируется —
громкость в `player-menu` свёрстана инлайн-разметкой напрямую в
`PlayerControls.jsx`, дублируя то, что уже сделано в `VolumeControl`. При
реализации: переключить `player-menu__volume` на реальный `VolumeControl`
(перевести его на новые иконки `IconMute`/`IconVolume` и токены) вместо того,
чтобы держать вторую копию той же логики.

## Тестирование

- Существующие тесты матчатся по `role`/`aria-label`, не по видимому глифу —
  подтверждено грепом (`★|☆|⏮|⏭|❚❚|▶|⋯|✕|🔇|🔊` не встречаются ни в одном
  `*.test.jsx`). Замена глифов на SVG тесты не ломает.
- `PlayerControls.test.jsx` придётся дополнить: сейчас `SeekBar` рендерится
  отдельно в `App`, после слияния — рендерится внутри `PlayerControls`, тест
  должен передавать `currentTime`/`duration`/`peaks`/`onSeek` и проверять
  наличие `role="slider"`/названия `Seek`.
- Живая проверка на задеплоенном сайте через Playwright: скриншот до/после,
  сверка, что панель одна, а не две.

## Не входит в этот этап

Генеративные обложки альбомов, процедурная геометрия под артиста, переход
между артистами, композиция камеры, специфика мобильных жестов — этапы 2–4,
отдельные спеки после этого.
