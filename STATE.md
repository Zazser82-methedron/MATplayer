## РАУНД 2 (2026-07-25/26) — по отчёту Gemini Deep Research

План: `docs/superpowers/plans/2026-07-25-matplayer-round2.md`.
Промпт и отчёт: `docs/2026-07-25-gemini-research-prompt.md` / `-report.md`
(в отчёте есть раздел «Сверка с реальным кодом» — Gemini писал по описанию,
а не по исходникам, и три его пункта пришлось скорректировать).

Реализовано 15 из 16 рекомендаций, **265 тестов** зелёных, каждая фаза проверена
вживую на задеплоенном сайте через Playwright (песочница не видит localhost).

- **Фаза 1 (арт-дирекшн):** порог bloom 0.82 вместо 0.2; три реально различимых
  режима частиц по `shader_presets.noise_type`; активированы God Rays; контраст
  лирики по WCAG; трёхступенчатая toon-рампа; починена лесенка деградации.
- **Фаза 2 (функции плеера):** громкость с кубической кривой + mute; очередь,
  shuffle, repeat; избранное и история в localStorage; deep links с тайм-кодом.
- **Фаза 3 (аудио-движок):** equal-power кроссфейд; общий шаг fetch+decodeAudioData;
  BPM-пульсации аватара с привязкой к фазе доли; waveform seek-бар.
- **Прочее:** карточка артиста с дискографией по свайпу вверх; схема трека
  расширена опциональными `audio_analysis` / `ai_adaptation`; удалён мёртвый
  `ArtistScene.jsx`; настоящий README.

**Найдено и починено 15 багов, ни один из которых не ловился тестами.** Самые
дорогие (все подтверждены измерением, а не рассуждением):
1. `uniforms` в `ParticleField` пересобирался при смене трека, но three.js
   держит объект по ссылке с момента компиляции шейдера → `useFrame` писал
   в объект, который рендерер не читает: частицы намертво замирали при
   переключении трека внутри артиста, `noise_type` не применялся.
2. zustand `persist` вызывает `setItem` на КАЖДЫЙ `set()`; `partialize`
   определяет только *что* пишется. С `audioBands`/`currentTime` это давало
   ~120 синхронных записей в localStorage в секунду. Лечится обёрткой
   `createDedupedStorage` (проверено счётчиком: 120 → 0 за 3 с).
3. `repeat: one` не зацикливал, а ОСТАНАВЛИВАЛ плеер и делал ⏮/⏭ мёртвыми
   (setTrack с тем же id не меняет зависимости эффекта), причём состояние
   сохранялось между сессиями.
4. `npm run dev` падал в белый экран: StrictMode дважды монтирует эффекты, а
   `createMediaElementSource` можно звать для элемента лишь однажды. Прод и
   e2e это не ловили (e2e гоняет preview).
5. Waveform рисовался сплошным прямоугольником — пик модуля по 43k сэмплов
   насыщается на лимитированном мастере (медиана была 100.5%). Заменено на
   RMS с нормировкой; стало 6–100%, медиана 87.8%.

## Task 19 — ВЫПОЛНЕН (2026-07-26)

Альбом «ЗМП» импортирован целиком: 26 треков, скрипт
`scripts/import-cupsize-tracks.mjs` (повторяемый, можно гонять заново).
Названия и настроения взяты из авторского массива `TRACKS` в
`cupsize-v2-story/main.js` — попутно исправились три неверных названия,
которые я раньше вписал руками («Flowers» на деле «Ванна, красный пол»).
Аудио пережато в 128 kbps: **173.9 МБ → 69.6 МБ** (плеер качает каждый трек
дважды — стримом для `<audio>` и целиком для анализа, поэтому экономия двойная).
В библиотеке 28 треков, поиск и переключение проверены вживую.

Заодно починен баг, который пользователь увидел на скриншоте: в тексте песни
показывался таймкод `[01:37.93] Пусть этот мир утонет...`. Причина в парсере
караоке — жадный `(.*)` брал текст до конца ФИЗИЧЕСКОЙ строки, а часть
исходника хранит переводы строк литеральными `\n` внутри JS-строки, и там
маркер следующей реплики утягивался в текст предыдущей. Теперь текст берётся
до следующего маркера. Лирика перегенерирована (`npm run migrate:lyrics`),
добавлен тест, запрещающий `[mm:ss` внутри текста у всех 26 треков.

## Stopped at
Все задачи плана раунда 2 закрыты. Открытый вопрос — **хранилище для треков
сообщества** (пользователь поднял его 2026-07-26, решения нет). Текущая схема
«mp3 лежат в git-репозитории» работает для кураторского шоукейса, но принципиально
не масштабируется на загрузки пользователей: каждая загрузка — это коммит,
размер репозитория растёт неограниченно, у GitHub Pages мягкие лимиты 1 ГБ на
сайт и 100 ГБ/мес трафика. Разбор вариантов — в ответе ассистента в чате;
ключевой аргумент: для музыки главная статья расходов не хранение, а исходящий
трафик, поэтому кандидат №1 — Cloudflare R2 (нулевой egress) + Workers/D1.
